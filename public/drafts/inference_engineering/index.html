Structured decoding

A computer scientist considers a few lines of text much more complicated than an Excel sheet with millions of rows. The reason for that is that text is not structured1, while a table is, making the table easier to process on a computer. One may then be interested in getting an LLM to output textual structured data2, to be used further down the road as an input to more traditional algorithms.

Say I’m looking for my LLM to output JSON descriptions of individuals with fields
a string name, a boolean is_male, age an integer and an extra optional field profession string.


{
    "name": "Alice",
    "is_male": false, 
    "age": 23,
}
// or
{
    "name": "Alice",
    "is_male": false, 
    "age": 23,
    "profession": "dentist"
}

  1. One may argue that this is wrong, and that valid sentences can be described by a grammar that’s Type-0 in the Chomsky Hierarchy, but without a finite (and manageable) description of this grammar, this is useless. To make matters worst, spoken languages change over time: words and rules continuously evolve. ↩︎

  2. Think custom subschemes of JSON or CSV for instance. ↩︎
